**Summary of follow-up discussion on Decision 1 (parsing-state design) — RESOLVED, ARCHITECTURE_PLAN.md already updated.**

We discussed Decision 1 (plain `TokenRules` data vs. the WIP per-facet trait design) through several rounds:

1. Claude clarified "the delta system": construct parsers return state changes as values; the engine applies them to produce new `Arc`-shared immutable states; reversion is structural (restore the parent `Arc`, never delta-undo). Claude retracted its overstated "contradiction" claim: getters don't conflict with deltas — *read-only* abstraction does; standard deltas also need a standard **update** contract.
2. I wanted settings behind getters for storage flexibility, including computed dependent settings (e.g. escape char = `#` in math mode, derived on the fly). Agreed benefit: cross-cutting rules centralized in the language definition instead of smeared across every delta writer. Required rule either way: stored-vs-effective split (deltas write stored config; effective values may transform it).
3. **Option A** (concrete state + per-getter `Lang` hooks): rejected by me — hooks "patch" the default storage model.
4. **Option B** (whole state behind `L::State: ParsingStateModel` trait: getters + standard-delta apply, storage-based default impl): Claude detailed the costs — engine wrapper still needed for derived caches; trait laws become the design (getter purity, delta locality, stored/effective semantics); compound getters need `Cow` shapes; capability traits for ext access; delegation boilerplate for "default plus one tweak"; poor debuggability (`dbg!(state)` lies).
5. I proposed **Option C**: all settings materialized as stored data, with a powerful `Lang` hook at logical transitions ("enter math mode") that rewrites dependent settings. Deciding argument: any effective-setting change *is* by definition a transition, so computed-per-read buys nothing over recompute-at-transition. C keeps hot-path field reads, best debuggability, and centralization (one finalize function); loses only swappable storage (speculative, recoverable later behind the getter surface — C keeps B's door open, not vice versa). C needs: (a) an airtight choke point — private fields, `derived()` as sole constructor of non-initial states; (b) override-interaction policy owned by the customizer's finalize (pure-normalization vs event-driven idioms), not core law.
6. I asked whether a mutating `apply()` is needed vs `copy_with(overrides)`. Answer: no mutation in the public contract, but the change-description must stay a reified **value** — producer and scope-decider differ (outward propagation: `\newcommand`'s delta is applied by callers to bases the producer never saw). Struct not closure (mergeable, inspectable, propagatable, batching for free). Final shape: `ParsingStateDelta<L>` = struct of optional overrides + `L::Event`s (typed pylatexenc "changed kwargs"), applied via `ParsingState::derived()`; `&mut` only internal pre-freeze; `Lang::finalize_transition(new, prev, events)` as the customizer hook; no `StateDelta` trait.

**DECIDED: Option C as above.** ARCHITECTURE_PLAN.md reflects it: §L2 rewritten, §4 records the A/B/C rationale, `Lang` gained `Event` + `finalize_transition`, `ConstructParser` returns `Option<ParsingStateDelta<L>>`, naming table + Decision 1 marked RESOLVED. Decisions 2–7 remain open.
